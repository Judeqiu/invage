### Extra steps for this version

- Set **`TELEGRAM_BOT_TOKEN`** on the invage process (shared `/opt/invage/.env`). Required for bot long-poll **and** task/system push.
- Optional **`TELEGRAM_BOT_USERNAME`** (e.g. `lexinvestor_bot`) for deep-link mint without `getMe`.
- Users link Telegram via WebUI **Settings → Telegram notifications → Connect**.
- Reseed agent KB (step 6) so peer `search_kb` sees help-first / async-task recipes.

## Breaking changes

- Task/system notifications **auto-push to Telegram** whenever `user.telegram_user_ids` is non-empty (framework beta.13). Unlink Telegram to stop DMs.
- Agents are biased to **schedule follow-ups** rather than lightly reject deferred asks — expect more `create_task` usage and `/tasks` traffic.

## Data / migration

- Framework may create under data root: `.telegram-link-codes.json`, `.notify-user-rate.json` (safe to delete).
- Agent KB seeds gain help-first entries; merge via `scripts/seed-agent-kb.mjs` (system-seed provenance updated).
- No user YAML schema migration.

## What changed (product)

- **Utarus `v3.0.0-beta.13`:** self-serve Telegram link, raw Bot API delivery adapter, auto-push when linked, `notify_user` tool.
- **Help-first contract** on Invester + Bookkeeper + Accountant + Investment Expert + Real Estate Expert: action plans; hard refuse only for true hard lines.
- **Async follow-ups:** `create_task` for observe-a-day / post-maturity re-plan / re-comps; task runner re-runs host Invester → re-consults peers; result to inbox + Telegram when linked.
- **`/guidance tasks`** (and aliases) documents watch/notify flows.
- Prior multi-agent peers (Investment Expert, Real Estate Expert, pure orchestrator host) remain the routing model.
