# Invage v0.3.8

Released 2026-10-10 from `main`. Utarus remains pinned to `v4.2.3`.

## Changes

- Expanded the authenticated `get_data_dictionary` / `query_data` interface from fixed projections to complete nested financial state, every accounting table, valuation snapshots, retained broker sync history and archived source data. Stock holdings, fund marks, encumbrances and broker listing identity are queryable alongside options.
- Archived JSON/XML/CSV/YAML queries retain stock trades, dividends, cash transactions and NAV fields that specialized importers omit. Original binary/unsupported or oversized sources remain accessible through byte-paginated raw reads.
- Added independent source versions for accounting/file/history pagination, exact monetary minor-unit handling and timezone-safe calendar dates. Reads remain tenant-scoped; no arbitrary SQL, writes or implicit FX. Incognito cannot retrieve Drive data through queries.
- Updated every agent's guidance to check holdings and relevant archives before declaring stock history unavailable, and to distinguish accounting reconciliations, premium cash flows and realized profit. See [query interface](../data-query.md).

## Validation and limitations

- TypeScript and 59 focused tests passed, including PostgreSQL accounting reads, calendar dates, complete archive fields, exact values, changed-source detection, user isolation, incognito restrictions and role registration.
- Verify deployed source hashes, package version `0.3.8`, framework `4.2.3`, both units active, local login endpoints and public login HTTP 200, and availability of the expanded query catalog.
- Stored-data queries do not fetch fresh quotes. Accounting entries and option premium cash flows do not establish realized profit on their own. Query limits fail explicitly; large/binary sources use original-byte pagination. Separate source reads are not a distributed transaction.
- Existing broker history gaps, failed syncs and unrelated legacy test failures remain outside this release.
