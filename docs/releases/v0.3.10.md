# Invage v0.3.10

Released 2026-10-11 from `main`. Utarus remains pinned to `v4.2.3`.

## Changes

- Section 03 adds a Rolls view with foldable account/underlying paths, transitions, contract legs and source evidence. Filters, dated replay, pagination, keyboard/mobile access, retry and empty states are supported; Open and History link to roll relationships.
- Read-only matching uses retained IBKR, Tiger, MooMoo and Webull archives, independently of current holdings. Explicit order linkage, IBKR execution inference, possible temporal candidates and review cases have distinct evidence labels. Conflicts/corrections can withhold account relationships. Conservative paths retain unverified continuity.
- Agents discover and retrieve the same relationships through `get_data_dictionary` / `query_data`, with transition, fill-reference, source, coverage and gap datasets. Queries preserve exact decimal cash, native currency/basis, account scope and independently versioned pagination. Incognito blocks these archive-derived datasets.
- Shared agent guidance and OptionsExpert instructions require evidence-based roll explanations. Cash credits/debits are not profit; shared orders alone do not establish rolls; a recorded replacement does not prove a current holding. Historical retrieval does not require live chain quotes.

See [dashboard implementation](../plans/2026-10-11-section-03-option-relationships.md), [agent query contract and examples](../plans/2026-10-11-agent-option-relationship-queries.md), and [broker findings](../audits/2026-10-11-victor-option-roll-linkage.md).

## Validation and limitations

- All 98 targeted tests across nine files passed, covering matching, authenticated API, generic queries, history/import and Chromium dashboard behavior. These cover evidence classification, exact cash, source/fill references, tenant isolation, replay, source-version changes, incognito restrictions, filters, pagination, keyboard access and responsive layouts. The TypeScript build and diff checks passed.
- Verify release source hashes, package version `0.3.10`, framework `4.2.3`, both units active/running, local/public login HTTP 200, and the live generic relationship dictionary and scoped queries before deployment is complete.
- Archive bounds are not proof of complete history. Readers impose explicit scan limits. Cash with missing metadata remains unavailable; possible/review links are not confirmed rolls. Stored paths do not prove continuous ownership or current positions. Relationship storage remains derived rather than persisted.
- Eight unrelated dashboard/history fixture failures reproduced on the pre-feature commit; this release does not repair those legacy investor-identity fixtures.
