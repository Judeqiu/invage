# Velovest dashboard loading progress

The authenticated `/api/domain/invage/dashboard?progress=1` response streams private server-sent events with actual processing stages and dataset counts. Without the query flag, the JSON response stays compatible. Authentication and target-user resolution happen before streaming starts. Events contain loading stages, counts and the same final dashboard payload; streamed failures send an error instead of success, without internal error details. A heartbeat keeps long waits connected and is cleared on completion or disconnect.

The WebUI reports records, market prices/currencies, valuation/history, broker trades, opening-day prices, completed-trade results and dashboard drawing. Opening-price lookup progress is based on completed lookups. Progress reflects work completed, not an invented countdown. The main dashboard becomes usable immediately after valuation and rendering; option history loads independently with its own one-minute deadline. A three-minute deadline bounds the primary request. A failed refresh keeps any displayed snapshot visible and explicitly marks the update failure.

Authenticated account snapshots are persisted in `data/cache/dashboard/snapshots`, survive process restarts and logins, and expire after 24 hours. The cache endpoint validates the authorized target user, account revision, current management settings, product profile and application-code digest. The dashboard requests `?progress=1&preview=1`: after one account read, the stream sends a `snapshot` event when a valid saved preview exists, followed by progress and the fresh `result`. The page displays the snapshot timestamp during revalidation. The separate cache endpoint remains available for existing report clients. The regular JSON and SSE dashboard endpoints always refresh valuation; only concurrent requests for the same account revision and refresh mode share an in-flight calculation. Cache responses remain private/no-store, and cache failures fall back to fresh calculations.

Trade journals, realized results and opening-lot details reuse persisted calculations only when their input records match. Relationship results additionally fingerprint account bindings, retained history and archive versions, so archive corrections invalidate the cache. Dashboard historical adjusted closes are cached for six hours to limit repeated provider requests while periodically revalidating corporate-action adjustments. Explicit Refresh bypasses that historical-price cache. Live option marks, matching probability-quote validation, equity prices and FX continue to run on every refresh. Generic historical-price callers retain uncached behavior unless they explicitly opt in.

Cache files contain derived dashboard data, use mode 0600, and are disposable. Each namespace retains at most 128 entries and 128 MiB, capped at 32 MiB per entry. Corrupt, incompatible and expired entries are misses. Archive read/parse failures are not persisted as relationship results. Application or dashboard code changes invalidate persisted entries on restart. Server `[Dashboard load]` logs report stage durations and total time, including the initial account read, without broker credentials.
