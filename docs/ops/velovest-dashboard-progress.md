# Velovest dashboard loading progress

The authenticated `/api/domain/invage/dashboard?progress=1` response streams private server-sent events with actual processing stages and dataset counts. Without the query flag, the JSON response stays compatible. Authentication and target-user resolution happen before streaming starts. Events contain loading stages, counts and the same final dashboard payload; streamed failures send an error instead of success, without internal error details. A heartbeat keeps long waits connected and is cleared on completion or disconnect.

The WebUI shows eight loading steps: records, market prices/currencies, valuation/history, broker trades, opening-day prices, monthly results, drawing the dashboard and option history. Opening-price lookup progress is based on completed lookups. Progress is based on work completed, not elapsed time or an invented countdown. The loader shows positions, trade records, snapshot counts and elapsed time, with a plain-language note during longer waits. It yields a paint before CPU-heavy drawing. Primary results can appear while option history finishes, and completion waits for that history request. Failures retain an interrupted progress indicator and a retry action. A three-minute request timeout is bounded and history timeouts keep the primary dashboard usable with a history-unavailable status.
