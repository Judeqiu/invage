# Read-only historical-data research

Use `node --import tsx scripts/fetch-broker-history.mjs <UUID|all> <absolute-private-output-directory>` with the account host's database environment. Optional `--broker=ibkr --year=YYYY` limits a retry to one broker/year. `--through=YYYYMMDD` clips coverage to a verified latest available statement date when IBKR rejects a request including days not yet reported. Flex SendRequest calls are paced by token at least 6.5 seconds apart (under 10/minute); HTTP calls time out after 30 seconds and statement polling allows three minutes for generation. The output directory must have mode 0700; response pages and reports are created exclusively with mode 0600. Every response file has a SHA-256 receipt. The tool reads enabled, bound Tiger, Webull and IBKR connections, requests historical records and writes research artifacts. It never saves investor state, updates coverage markers, publishes notifications, deploys code, or restarts services. Running a committed copy from an isolated operator directory can select existing installed clients with `INVAGE_RESEARCH_MODULE_ROOT`.

This is collection and coverage research, not a replacement for the adapters or a production historical import. The research artifacts are not visible to the agent's generic queries until a reviewed normalization/import uses `BrokerStatement.history` and `InvestorState.broker_history[channel]`. Never substitute cumulative order fills for individual executions, infer cash from disappearing holdings, or mark partial research complete. Current holdings must not filter the historical universe.

## Sources verified 14 October 2026

- [Tiger orders and transactions](https://docs-en.itigerup.com/docs/orderinfo-java): request all orders with stable date filters and cursors; request stock and option transaction pages independently. Continue on an empty page when `nextPageToken` remains. `order_transactions` supports Prime/Paper accounts; Global account execution history needs a separate supported route. An all-time request does not prove broker retention or account inception. Other asset classes, cash activity and lifecycle records are separate coverage work.
- [Webull order history](https://developer.webull.com/apis/docs/reference/order-history/) and [changelog](https://developer.webull.com/apis/docs/changelog/): the Trading API supports explicit `start_time`/`end_time` and cursor pagination. The documented two-year restriction was removed in July 2026. Retrieve all order groups, including closed instruments. Cumulative fill quantity/price is not a distinct fill ledger. The new List Order Executions endpoint belongs to the separate Broker API; Trading API credentials do not establish access to it.
- [IBKR generate report](https://www.interactivebrokers.com/docs/web-api/flex-web-service/using-flex-web-service/generate-the-report): `fd` and `td` on SendRequest override the query period. The operator wraps the existing Flex transport, without modifying live sync. Request each of the current and four previous calendar years, using configured Activity and Trade Confirmation query IDs where available. [IBKR retention guidance](https://www.ibkrguides.com/orgportal/performanceandstatements/flex.htm) describes those available years. Check actual XML statement dates and sections: configured templates can omit trades, return aggregates, or restrict accounts. Only bound-account execution-level rows contribute to research counts; never sum Activity and Confirmation copies as additional fills. CSV cannot prove the XML account/date scope and is flagged for template correction.

Futubull/OpenD is also present in the connector catalog but was not connected on the inspected Velovest accounts. Its current snapshot bridge does not fetch history. Historical order/deal endpoints would require an available authorized OpenD gateway and their own pagination/date-window review; no gateway was started or reconfigured by this research task.

Fetch failures are reported per connection/section and successful pages survive. Pagination loops, malformed arrays, or reported foreign account IDs stop that section. Missing credentials and broker permissions are not repaired automatically. A manifest retains explicit gaps even if every requested page returns successfully.

## Verified fetch outcome

The 14 October read-only run retrieved the following from connected Velovest accounts:

| Account / broker | Retained research records | Verified coverage and remaining gaps |
| --- | --- | --- |
| Victor / Tiger | 1,994 unique orders, 1,889 unique transactions (13 stocks, 1,876 options), 300 option-order legs | Requested since 2000; returned fills range from 31 October 2022 through 6 October 2026. Every fill links to a fetched parent order. Retention/inception and other activity are not proved. |
| Victor / Webull | 83 orders: 78 options, five equity; 62 filled and 21 cancelled | These are cumulative order records, not individual executions. Preserve partial fills on cancelled orders and multi-leg structures; do not fabricate a fill ledger. |
| Victor / IBKR | 3,719 distinct execution-level trades: 3,499 options, 220 other securities | Full returned calendar reports for 2023–2025 plus 2026 through 12 October. Requested 2022 returned error 1003 (statement unavailable). |
| jude.qiu / IBKR | 13 option executions | 2026 through 12 October. Prior-year requests returned statement unavailable. |
| judetest1 / IBKR | 13 option executions | 2026 through 12 October. Prior-year requests returned statement unavailable. Counts remain scoped to this connection; do not add them across accounts without verifying custody ownership. |
| Futubull/OpenD | No fetch | No configured account/gateway on inspected accounts. |

A transient IBKR 1019 generation failure for 2024 succeeded on retry. Requests including 14 October returned 1003, while explicit 2026 requests through the verified latest statement date (12 October) succeeded. The tool now supports that cutoff and token-aware pacing. API errors are coverage gaps, not evidence of no trades.

Responses and checksum receipts were copied to a private local research directory. The consolidated report is `/tmp/velovest-other-broker-history-20261014/research-report.json`. No live portfolio, cash, retained history, service code or service lifecycle was changed.

For a later integration, normalize into the existing shared history contract, retaining all stock/option executions and orders independently of holdings. Tiger's parent order legs carry exact multipliers and can enrich matching expired contracts; standalone orders do not provide that field. Order-level commission/GST must not be duplicated across fills. Webull order quantities and fills require separate order-level representation until verified execution access is available. IBKR execution rows retain explicit fees and contract terms; exclude aggregate rows and deduplicate Activity/Confirmation reports by account-scoped trade identity. Keep raw fields available as evidence and completeness gaps queryable.
