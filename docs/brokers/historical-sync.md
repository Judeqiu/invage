# Broker history and sync

`BrokerStatement.history` and `InvestorState.broker_history[channel]` are the shared history contract. History is bound to broker, immutable custody channel and account ID. It contains all returned executions (securities and options), parent orders, order legs, coverage and explicit gaps. Decimal quantities and money stay strings. Missing multipliers, cash, currencies and fees stay null. Historical executions do not change today's cash or holdings and are not automatically realized P/L.

Settings provides **Sync latest** and **Full sync** for each account. The existing sync API/tool defaults to latest; `{full_sync:true}` explicitly requests the backfill. Scheduled sync always uses latest. Latest sync uses the retained broker checkpoint with a two-day overlap, or the last two days when history is absent. Missing history and partial coverage never trigger automatic backfills. Full sync requests all available history and the current holdings/cash snapshot. Repeating Full sync safely merges existing records.

`historical_imported` records the explicit full import independently of completeness. A successful import can still have expired-contract metadata, unavailable years, fee or unsupported-endpoint gaps. Latest sync retains those gaps and all previously fetched records. `full_history_synced` continues to describe complete coverage, not whether the button was used. Failed pages do not advance a checkpoint; conflicting execution economics abort the apply. Decimal-equivalent duplicates merge by account-scoped ID. Historical snapshots never replace current holdings: the common apply path uses only the fresh snapshot and atomically persists validated history with the investor revision.

## Tiger, Webull, IBKR and Futubull

Tiger requests all parent orders plus stock/option transaction pages using the chosen bounds, including closed-only accounts. Parent orders referenced by new fills are fetched even if created before the latest window. Authoritative order-leg multipliers enrich exact expired contracts; other metadata and unreported intent remain explicit gaps. Broker-rounded stock cash is preserved, with exact-decimal verification against currency rounding. Final single-contract option order commissions/GST are allocated only when complete fills reconcile. Global accounts retain order history but explicitly lack unsupported transaction coverage.

Webull stores every returned order and its legs in the shared history model, including cancelled partially filled orders. Latest requests use recent bounds; Full sync pages available history. Its Trading API returns cumulative order fills, so new sync does not fabricate individual executions. The separate Broker API execution permission is not assumed, and the gap is queryable. Existing legacy evidence remains retained.

IBKR Full sync fetches the current snapshot and available yearly Activity Flex reports for the current/four previous calendar years. The current report's actual latest date caps requests, avoiding unavailable future reporting days. Latest sync makes no yearly backfill requests, filters retained executions to the recent checkpoint window, and checkpoints the actual reported date. Annual historical snapshots supply executions only; they never replace current positions/cash. Each raw yearly XML report is archived for generic source queries. Duplicate trades merge by account/trade ID. Missing years and omitted sections remain gaps; unavailable reports do not establish no trades. Flex parent IDs are retained, but are not a complete order/leg ledger. Flex timezone stays explicitly unspecified when not supplied. Existing CSV snapshot parsers continue working, with an explicit historical-coverage gap until the configured query returns execution-level XML.

Futubull's read-only OpenD bridge requests historical deals and orders with explicit dates and the bound live `acc_id`. Decimal fields and IDs are serialized as strings. Closed options survive in generic history even when exact contract multipliers are unavailable; unknown cash/fees remain null. OpenD must already be available and authorized; sync does not start or reconfigure a gateway.

## Moomoo

The Cloud API adapter requests explicit bounds (full requests start at 2000-01-01, rather than the API's default 90-day window), reads every fill/order page for US and HK, and batches parent order details at 50 IDs per request. Parent details include IDs referenced by newly fetched fills, even if the parent was created before the incremental window. Raw responses are archived for source-level queries.

Options include closed contracts and protective long legs independently of current holdings. One exact-contract resolver combines quote metadata, explicit position multipliers and authoritative option parent-leg premium multipliers. Contradictory sources stop the import. Missing expired-contract metadata retains the execution with unknown cash and a retryable gap, while other valid executions and current snapshots can be applied. Missing current-held contract size stops snapshot replacement. Order-detail failures retain partial history; Full sync can explicitly retry older gaps without forcing every latest sync to backfill. Fees not supplied by these Cloud endpoints remain unknown; gross premium is never labeled net after fees.

Completeness describes the requested data returned by these broker APIs, not a guarantee about records the broker no longer exposes. Historical dividends, transfers and lifecycle events are not inferred from fills or disappearing holdings.

## Agent queries

The data dictionary exposes `broker_executions`, `broker_orders`, `broker_order_legs`, `broker_history_sync`, and `broker_history_gaps`. Always scope joins with broker/channel/account. Execution `clock` supplies the timezone of the retained local timestamp. Inspect coverage and gaps before claiming historical totals. `option_executions` remains the existing common projection of verified option execution cash. The `financial_state` source also exposes the retained shared history; archived raw responses retain fields outside normalized projections.

The operator backfill script `scripts/backfill-moomoo-executions.mjs` uses the same planner, merge and projection. It explicitly requests full history; its default is read-only. `--apply` archives prior execution/history state and updates retained history without replacing cash or holdings.
